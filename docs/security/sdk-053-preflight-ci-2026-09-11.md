## 本轮修改

新增 bridge-ci.yml：push 到 sdk-053-bridge、相关 PR 或手动入口执行测试；验证 Linux AMD64/ARM64 包和 Dockerfile；上传候选 tar.gz、哈希、构建信息。权限为 contents:read，不创建 Release、不推送镜像。

Dockerfile 与发布 CI 复用 scripts/build-bridge-release.sh，避免两套 WasmVM 版本/构建参数漂移。镜像构建也执行 version/init 冒烟验证。Linux 和 Docker CI 尚未在远程运行：本轮修改没有提交/推送，本机 Docker 服务不可用。

升级保护放在 App.New 的 BaseApp 初始化/StoreLoader 之前，只在匹配桥接计划且最新提交高度为 H−1 时执行：

1. 读取 multistore 提交信息，按提交版本打开只读 IAVL 树并核对根哈希。
2. 要求 feeibc 树为空。
3. 另查旧 bank 存储中的 feeibc 模块账户余额键，任何条目都拒绝删除。该策略保守：即使异常存在零余额条目也会拒绝，需调查处理，不自动清理。
4. 要求源模块版本表符合 0.4.4；允许已在主网发现的历史 crisis=2 条目，拒绝未知条目或错误版本。
5. 要求旧 upgrade/Consensus 存在、可解码且共识参数有效。零值 Version 消息省略时按默认值验证，避免空指针。
6. handler 再验证源版本与共识参数，作为迁移入口的第二层检查。

本轮主网只读查询高度 17,250,570 的 ModuleVersions 与预期一致，并保留 crisis=2。源版本断言来自 0.4.4 固定依赖源码核对，并以此次查询交叉确认；版本表不能单独证明整个数据库来自可信源，仍须真实快照演练。

前置检查不代替同版本兼容层，也不进行退款或改写。遇到非空费用、坏参数、错误版本，会明确停止，操作员应处理源状态或候选代码，而不是跳过检查。对正常主网来源要求精确旧 Consensus 记录；依赖其他旧参数布局的开发快照不属于当前生产放行路径。
