不要把“移除 400 次上限”与“跳过 recheck 密码学计算”合成一个修复：
前者改变共享资源分配／提案规则，后者只消除已验证字节的重复计算。
上调预算有助于吞吐，但增加块内可能接受的工作；直接删除则需要完整替代
容量论证。原生 ML-DSA 已经参与这个共享预算，不能只测扩展账户。

## 参数精简逐项处理

| 建议 | 本次状态与理由 |
|---|---|
| 两种验签 gas 合并／从 x/auth 动态读取 | 两者继续使用固定 SDK 基准默认／下限 750；不回退 250,000。可合并，但读取实时 x/auth 值会引入跨模块治理耦合，需明确已有显式参数及升级语义。算法相同不等于整个 Ante 开销相同。 |
| 每笔 16 次改常量／移除 | 暂保留。7 个 SDK 签名是当前 auth 参数约束，不是不可变协议常量；还需区分多签叶子、独立 payer、生命周期证明与参数未来变更。不能只由单一 send 算例断言永远不可达。 |
| MaxPqcSigners=8 移除 | 可考虑固定而非治理；须保留恶意 wire 输入的解码前条目上限。SDK 合法交易的 7 签名限制不能替代解码前防分配放大。 |
| MaxPqcAuthBytes=64 KiB 改常量 | 可考虑；同样保留解码前绝对 256 KiB 上限及规范化约束。约 23.6 KiB 是特定合法形态估计，不是全部地址／整数编码宽度的严格上界。 |
| 每角色历史记录 16 改常量 | 可以另做精简，但需要确定已有 active/pending 参数及导出导入兼容策略；不是必须紧急改动的漏洞。 |
| allowed_algorithms 改常量 | 当前仅 ML-DSA-65；可缩小治理面，保留算法编号及不支持算法拒绝。需要决定未来算法迁移接口。 |
| DISABLED 与 OPTIONAL 合并 | 当前自保护仍强制有效，二者相关运行行为重叠；可减少公开选项，不能重用旧枚举值或静默改变已有状态含义。 |
| 全局 REQUIRED | **已禁止首版配置**。保留枚举，不映射 OPTIONAL；REQUIRED_FOR_REGISTERED 仍合法。未新增多签/Amino 支持。 |
| CLOSED／不可逆 cutoff 移除 | 未改。确有误治理风险，但注册仅靠经典签名，移除截止机制也会改变面对经典私钥被破解时的安全边界。需明确首版长期 OPEN、可逆关闭或保留不可逆承诺三者中哪一种产品策略。 |
| PAUSE_PQC_TRANSACTIONS 移除 | 未改。不能仅凭“还有经典签名”证明可删：PQCAuth 的威胁模型包括经典私钥已泄露／被破解。暂停是否有用要区分模块实现 bug、PQC 算法失效和治理响应能力。恢复逃生路径本身仍依赖 ML-DSA，不是算法失效后的万能恢复。 |

这些不是“已经确定没必要所以漏删”的字段，而是待确认的协议范围。
减少治理参数有价值，但持久化字段、迁移、签名意图、客户端、演练都需要
一起处理；不要为了减少行数绕过原有延迟、不可逆承诺和输入上限防线。

## 请 Claude 核对的安全前提

1. **当前应用没有启用 SDK unordered transactions。** 本次用实际
   AccountKeeper 配置和 ABCI 测试锁定此点。恢复签名文档的 policy version
   来自状态；今后开启无序交易前必须重新论证 recheck 的状态绑定，不能仅以
   “SDK 自己也跳验签”作为完整证明。
2. 三个 recheck 路径跳过 crypto 但保留 gas 与状态检查。测试中直接向 ABCI
   注入从未通过 New 的坏签名，Recheck 成功是信任边界演示，不是真实入池。
   同一字节在 New 和 Finalize 仍失败。检查是否有应用特有路径会破坏
   “重查的是已经通过 New 的相同字节”前提。
3. 本次真实签名回归覆盖 owner 与独立受保护 payer，轮换、恢复和取消恢复；
   另覆盖旧 key/policy、暂停生效、sequence 变化。若需新增情形，请提供具体
   生命周期状态轨迹，不能只更改测试中的 Recheck 标志来模拟真实网络。

## 需修正／补证的 benchmark 推论

- SDK 微基准可支持 750 的同算法基准；不能独自证明所有大 body、最大 signer、
  失败签名和多次序列化组合的块耗时均小于某一数值。本次包装层 256-byte
  测试接近 SDK，但 64 KiB 输入仍有复制／封装成本。
- “5000 × 单笔时间”是估算，不是满 mempool 的多验证人实测。当前新回归是
  200 笔、3 轮真实应用 recheck；没有声称已经完成 5,000 笔四节点压测。
- “400/block 不保护任何东西”结论过强：它确实限制提案内计数，也确实可能
  造成低效额度竞争。是否冗余需与有效 block gas/bytes、最大签名规模、
  CheckTx/recheck 和 proposer 排序一起验证；块预算不是入池限速器。
- 5,200/92,000 DORA/日不能直接作为已验证攻击成本。应核对实际 fee、
  min-gas-prices、**声明 GasWanted**（不是只看 GasUsed）、排序和吞吐；
  无效交易的入池 CPU 不会因为记了 gas 就自动收费。本次不发布固定攻击报价。
