# PQC 最近四天工作总结

> 统计范围：2026 年 8 月 27 日下午至 8 月 31 日。本文用于团队汇报，重点说明本阶段完成的链端优化及验证结果。

## 1. 总体进展

本阶段将 PQC 工作从“核心功能可运行”推进到了“安全边界可控、升级前可审计、资源消耗可约束、跨链流程可验证”的阶段。工作同时覆盖了经典账户的 `pqcauth` 双因子保护、Cosmos SDK 原生 ML-DSA 账户、CometBFT ML-DSA 共识，以及 IBC 跨链兼容性。

## 2. 主要工作与优化

| 方向 | 完成内容 | 解决的问题 |
| --- | --- | --- |
| 授权安全 | 加固 `authz`、`group`、`gov`、Wasm 嵌套执行边界；受保护账户只能向已满足 PQC 要求的执行方授权；间接执行密钥生命周期消息会在 Ante 阶段提前拒绝 | 防止通过 `MsgExec` 或嵌套消息绕过 PQC 校验和密钥生命周期限制 |
| Feegrant 安全 | 新增确定性的 `granter -> grantee` 反向索引、到期队列和链上同步逻辑；注册或启用保护前检查未撤销的代付授权；升级审计对索引与 SDK 原始状态做双向核对 | 防止旧代付权限在账户启用 PQC 后继续形成权限或经济边界漏洞，同时避免 Ante 全局扫描 |
| 迁移与注册 | 强化 `OPEN / FRESH_ACCOUNTS_ONLY / CLOSED` 注册窗口；`FRESH` 要求注册是账户第一笔发出交易；新增 `protection-readiness` 预检；原生 ML-DSA 账户被视为已满足 PQC，不允许重复注册第二因子 | 明确经典账户迁移规则，避免已暴露经典公钥的账户被错误认定为“新账户”，并保证原生 PQC 与 `pqcauth` 各自适用正确的账户类型 |
| Gas 与抗 DoS | 建立确定性 PQC 验证 gas 模型；新增每笔交易和每个区块的验证次数上限，默认分别为 16 和 400；Ante、`PrepareProposal`、`ProcessProposal` 在执行昂贵验签前统一检查预算 | 防止恶意交易或恶意提案通过堆叠 ML-DSA 验签消耗验证人 CPU，避免只依赖 gas 价格控制资源 |
| 升级安全 | 新增 `dorad pqcauth audit-state` 离线审计和链上 invariant，覆盖账户策略、密钥状态、授权及 feegrant 索引一致性；异常状态按 fail-closed 处理 | 在正式升级前发现不一致状态，降低升级后账户锁死或节点因状态异常停止处理区块的风险 |
| 性能与容量 | 完成受限资源双节点的稳态、饱和和对抗压测，并记录确认延迟、区块容量、gas、交易体积和恶意交易拒绝结果 | 给出 PQC 交易的实际容量边界，验证高负载和恶意流量下的链端防护是否有效 |
| PQC-IBC | 实现 ML-DSA CometBFT header 构造与验证、原生 ML-DSA relayer 签名适配和双链测试框架；在真实节点上完成 Ed25519 到 ML-DSA-65 共识密钥轮换后的双向 ICS20 中继 | 证明共识密钥更换为 ML-DSA 后，IBC client update、状态证明、收包和确认流程仍可连续运行 |

## 3. 关键实测结果

### 3.1 交易容量与攻击流量

测试环境为同一台 20 CPU、62 GiB 服务器上的两个独立节点，每个节点限制为 10 CPU、30 GiB 内存；负载由经典交易、`pqcauth` 混合签名交易和原生 ML-DSA 交易组成。

- 30% 和 60% 稳态负载分别完成 6,780 和 13,620 笔交易，失败数均为 0，P99 确认延迟约为 3.4 秒。
- 90% 压力下完成 20,400 笔交易，观测到单区块最多约 380 笔交易；P99 延迟上升至约 27.4 秒，说明系统已进入排队和饱和区间，该档位不应直接作为生产容量目标。
- 对抗测试持续注入 36,000 笔非法、超长、非规范或错误 sequence 交易，链上接受数为 0；同时 13,620 笔合法交易全部成功，吞吐约 111 TPS，P99 约 3.54 秒。

### 3.2 PQC-IBC 双链模拟

- 两条链均从 Ed25519 共识密钥平滑轮换为 `ML-DSA-65`，轮换后继续出块。
- 完成轮换前 A → B，以及轮换后 A → B、B → A 的 ICS20 转账、client update、`RecvPacket` 和 `Acknowledgement`，全部交易 `code = 0`。
- ML-DSA-65 IBC header 从 Ed25519 的 855 B 增至约 11.8 KiB，约为 13.8 倍；单次 client update gas 从 267,819 增至约 377,200，增幅约 40.8%。这些数据为后续配置 `block max bytes`、gas 和 relayer 容量提供了依据。

完整交易记录和浏览器链接见 [PQC-IBC 双链真实节点模拟报告](pqc-ibc-real-node-simulation-2026-08-31.md)。

## 5. 当前结论与下一步

当前实现已经覆盖账户交易、授权边界、资源预算、升级审计和 IBC 主流程，能够作为后续测试网升级与参数标定的基础，但尚不能据此直接宣称生产环境“端到端全部抗量子”。下一阶段建议重点完成：

1. 在真实多验证人、跨机器和网络延迟/丢包条件下复测共识轮换与 IBC。
2. 按目标验证人硬件重新标定 ML-DSA gas、每区块验证预算和 `block max bytes`。
3. 扩展 IBC timeout、ICA、Wasm IBC callback 等异常及应用路径覆盖。
4. 在正式升级前处理依赖安全扫描中的上游漏洞，并执行全量状态审计和回滚演练。
